## Why

Decisions and plans lived in handoff files, Claude's private memory and `DesignNotes.md` — each
semi-persistent: a handoff is stale the moment its session ends (`HANDOFF-MtgReal.md` still said
"next: build the UI" a week after the UI was done), memory is invisible to Shayne, and DesignNotes
mixes deferred ideas with engine ceilings. The project is big enough to want one place that says
where every piece of work stands, and IDs short enough to refer to work without re-explaining it.

## Requirements

- [x] One file per story in `docs/stories/`, owned by the project branch
- [x] IDs `AREA-N`, tasks `AREA-N.M`; areas for `mtg-real`: MC, TBL, AI, LIM, DATA, DEV
- [x] An index with a hand-ordered "Next up" and a generated table of every story
- [x] `tools/stories.py` fails on a duplicate id, a mismatched file name or area, a foreign task id,
      or a "Next up" entry that is missing or closed — and proves it with `--selftest`
- [x] The root `CLAUDE.md` points at `docs/stories/` and makes keeping a story current — requirement
      changes included — a rule of every task
- [x] `/pre-commit` checks the index and that the change's story was updated
- [x] Open work on `mtg-real` migrated into stories; finished work gets one short `done` story each
- [x] `HANDOFF-MtgReal.md` retired once its unhomed lessons have moved (Shayne confirms the delete — it is untracked)
- [x] Shayne reviews and asks for the commit

## Decisions

2026-10-16, Shayne (interview — do not re-ask):
- **Location:** `docs/stories/`, next to `docs/findings/`.
- **Branches:** each project branch owns its own stories (mtg-real, KIN, the core branch). Stories
  for shared code are cherry-picked. Separate repos were considered and rejected: the purpose is
  exploring how to build games with AI, not a long-term product. Re-evaluate if it gets messy.
- **IDs:** area prefix + number (`MC-12`). Shared stories are `CMN-`, numbered on `main` only.
- **Hierarchy:** story → task checklist. No epics.
- **Migration:** open work only; one short `done` story per big finished piece, so it can be referenced.
- **Old docs:** handoff files retire — a story's Next section replaces them. `DesignNotes.md` stays as
  the reference for deferred ceilings; a story links to an entry when it takes one up.
- **Ordering:** a hand-ordered "Next up" list in the index; no priority field.
- **Template:** the full one — Why, Requirements, Decisions, Tasks, Next, Log.
- **Index:** generated by a small script that also checks for drift.
- **Linking:** commit subjects start with the story ID. CLAUDE.md gets the rule that a story is
  updated in the same step as the work, **including any change to its requirements**.
- Not wanted yet: a `/story` skill — add one if the manual steps get repetitive.
